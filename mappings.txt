# Android Manager API Mappings - Java SDK and NDK Functions

This document provides comprehensive mappings of our Nim manager APIs to the underlying Android Java SDK and NDK functions that need to be called via FFI/JNI.

## Core System Managers

## System Services Access Pattern

All Android system services follow this pattern:

```java
// Get system service
ServiceManager service = (ServiceManager) context.getSystemService(Context.SERVICE_NAME);

// Use service methods
service.someMethod(parameters);
```

**Service Constants**:
- `Context.AUDIO_SERVICE` → AudioManager
- `Context.VIBRATOR_SERVICE` → Vibrator  
- `Context.NOTIFICATION_SERVICE` → NotificationManager
- `Context.LOCATION_SERVICE` → LocationManager
- `Context.CAMERA_SERVICE` → CameraManager
- `Context.SENSOR_SERVICE` → SensorManager
- `Context.POWER_SERVICE` → PowerManager
- `Context.CONNECTIVITY_SERVICE` → ConnectivityManager

## JNI/FFI Implementation Notes

### 1. Service Acquisition Pattern
```nim
proc getSystemService(context: JavaObject, serviceName: cstring): JavaObject =
  # Call context.getSystemService(serviceName)
  # Returns the system service manager object

proc getAudioManager(context: JavaObject): JavaObject =
  return getSystemService(context, "audio")
```

### 2. Method Invocation Pattern
```nim
proc callJavaMethod(obj: JavaObject, methodName: cstring, signature: cstring, args: varargs[JavaValue]): JavaValue =
  # Standard JNI method invocation
  # Gets method ID and calls via JNI

proc setRingerMode(audioManager: JavaObject, mode: int) =
  discard callJavaMethod(audioManager, "setRingerMode", "(I)V", mode.toJavaValue)
```

### 3. Callback Registration Pattern
```nim
proc registerCallback(manager: JavaObject, callback: proc) =
  # Create Java callback proxy object
  # Register with Android service
  # Handle callbacks from Java → Nim
```

### 4. Permissions Required

Many APIs require permissions in AndroidManifest.xml:

- **Audio**: No special permissions for basic playback
- **Vibration**: `<uses-permission android:name="android.permission.VIBRATE"/>`
- **Location**: `<uses-permission android:name="android.permission.ACCESS_FINE_LOCATION"/>`
- **Camera**: `<uses-permission android:name="android.permission.CAMERA"/>`
- **Network**: `<uses-permission android:name="android.permission.INTERNET"/>`
- **Storage**: `<uses-permission android:name="android.permission.WRITE_EXTERNAL_STORAGE"/>`

This comprehensive mapping provides the exact Android SDK methods and NDK functions needed to implement each Nim manager function through JNI/FFI bindings.

### Smart Permission Handling

```nim
proc requestPermissionSmart*(pm: PermissionManager, 
                           category: PermissionCategory,
                           mandatory: bool = false,
                           customRationale: Option[string] = none(string)): Future[PermissionResult] =
  # 1. Check if already granted
  let permissions = getPermissionsForCategory(category)
  let alreadyGranted = permissions.filterIt(pm.checkPermission(it))
  
  if alreadyGranted.len == permissions.len:
    return success(PermissionResult(granted: permissions, denied: @[]))
  
  # 2. Check API level - only request runtime permissions on API 23+
  if Build.VERSION.SDK_INT < 23:
    # On older versions, permissions are granted at install time
    return success(PermissionResult(granted: permissions, denied: @[]))
  
  # 3. Show rationale if needed
  let rationale = customRationale.get(getDefaultRationale(category))
  let needsRationale = permissions.anyIt(pm.shouldShowRationale(it))
  
  if needsRationale:
    await pm.showRationaleDialog(rationale, category)
  
  # 4. Request permissions
  let result = await pm.requestPermissions(permissions)
  
  # 5. Handle denial with retry option
  if result.denied.len > 0 and mandatory:
    let retryResult = await pm.showRetryDialog(category, result.denied)
    if retryResult == DialogResult.Retry:
      return await pm.requestPermissionSmart(category, mandatory, customRationale)
    elif retryResult == DialogResult.Settings:
      pm.openAppSettings()
      
  return result

proc showRationaleDialog(pm: PermissionManager, rationale: string, category: PermissionCategory): Future[bool] =
  # Show user-friendly dialog explaining why permission is needed
  # Include screenshots or icons showing the feature
  # Clear "Allow" and "Cancel" buttons
  
proc showRetryDialog(pm: PermissionManager, category: PermissionCategory, denied: seq[string]): Future[DialogResult] =
  # "This feature requires [permission]. Would you like to:"
  # - "Try Again" 
  # - "Go to Settings"
  # - "Continue Without" (if not mandatory)
```
